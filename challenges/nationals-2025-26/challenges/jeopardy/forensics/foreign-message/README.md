## Description

Challenge consists of an encryption key encoded in Russian text in a telegram, and a document with a flag encrypted with GOST algorithm and uuencoded.

### Walkthrough

<details>
<summary>(expand to read)</summary><br>

We begin by looking at [telegram.txt](./release_files/telegram.txt), but if we decode it naively we get gibberish text. We have to remember that the message is from Russia, and closer examination of [telegraph alphabet](https://en.wikipedia.org/wiki/Baudot_code#ITA2) shows that there is a special standard, **MTK-2**, that encodes Russian letters. If we use it to decode the message and then use any online tranlator, we can decode the following message:

```
КЛЮЧ ШИФРОВАНИЯ: СТО ШЕСТНАДЦАТЬ, ТРИДЦАТЬ ДВА, ...
```

It translates into:

```
ENCRYPTION KEY: ONE HUNDRED SIXTEEN, THIRTY TWO, ...
```

Telegram text contains 32 bytes of the encryption key.

We now turn attention to the message file. It's an e-mail with an embedded binary file that can be decoded using legacy utility `uudecode`. The result is an encrypted file.

It is not clear what the encryption algorithm is, but we again have to remember that the message comes from Russia. The algorithm turns out to be a standard [Russian encryption algorithm GOST](https://en.wikipedia.org/wiki/GOST_(block_cipher)). Lots of implementations exist for it, including [gostcrypto](https://pypi.org/project/gostcrypto/). 

The decrypted file is an RTF from Russian Foreign Ministry announcing establishing of a communication channel and proposing a new encryption key, which is the flag.

Solution steps are encoded in [solve.py](./solve_files/solve.py).

</details>
